# Financial methodology

See [specialized workflows](specialized_workflows.md) for AP, AR, gateway, intercompany and GL contracts. Bank matching uses exact currency/account/sign, Decimal amount tolerance (default zero), a configurable date window (default three days), and a nonempty exact reference. Fuzzy assistance additionally requires exact counterparty agreement and description similarity; it is supporting evidence, not a calibrated probability.

Candidates are accepted only when both sides have a unique eligible match. One-to-many/many-to-one matching enumerates bounded subsets sharing a nonempty reference; overlapping subsets stay open. The default group maximum is four, configurable up to six, with at most sixteen candidates per subset pool. Cross-ID duplicate fingerprints are excluded for manual review, and every remaining unmatched record remains visible. Monetary totals remain separate by currency; no implicit FX conversion occurs.

Canonical ingestion supports CSV, XLSX, JSON and manual records, source-column mappings, preview and reusable templates. It validates required fields, signed debit/credit consistency, ISO currency precision, finite monetary range, dates, timezones and duplicate IDs. Original row values and per-field transformation records remain immutable. Value/posting dates and UTC timestamp conversion are recorded. The ISO registry comes from pycountry, with Babel precision; XXX/XTS are not accepted. Excess precision is rejected rather than rounded silently. Operator CURRENCY_PRECISION_OVERRIDES can configure 0–6 decimals per registered currency; the selected precision is recorded in normalization metadata.

Independent journal validation checks finite nonnegative line values, one debit or credit per line, positive equal totals, evidence identity, independently normalized source integrity, currency, supported correction evidence, financial impact, tenant account validity, policy version, posting period and approval level. Executable drafts currently require an explicit configured bank-charge source code and a registered currency with validated journal precision; other financial corrections deliberately remain manual review recommendations.

Simulated cash balances are recalculated from immutable adjustments and reversals separately from original source totals. Reports also present workflow-specific accounting equations, such as invoice less credits less payments and gateway gross less deductions. No LLM determines whether an accounting equation balances.
